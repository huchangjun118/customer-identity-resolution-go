# customer-identity-resolution-go

客户身份归并与统一画像。来自不同渠道的身份信号在本进程 + 本地存储内完成归并、
冲突消解、误合撤销、拆分再归并、同意与权限管控，不依赖外部服务与真实凭据，
同一输入在任意到达顺序、任意批次划分与任意并发度下结果逐项一致、可在本地稳定复现。

## 快速开始

```bash
go build ./...
go test ./... -race
go run ./cmd/idres   # 本地样本信号流演示
```

## 核心概念

| 概念 | 说明 |
| --- | --- |
| `Signal` | 一条渠道身份信号：标识集合 + 属性集合 + 同意范围 |
| `Identifier` | 可匹配标识，如 `("email","a@b.com")`，规范化为 `type:value` 键 |
| 身份簇 | 标识图上的连通分量；簇 ID 为分量内字典序最小的标识键 |
| `Profile` | 簇在某一版本上的完整自洽画像，对外只暴露完整版本 |
| WAL | 本地追加日志（`identity.wal`），重启重放恢复全部已提交状态 |

## 归并语义

- **链接规则**：一条信号的全部标识两两连通；共享任一标识的信号归入同一身份簇。
- **确定性**：并查集代表元恒为集合内字典序最小的标识键，与信号到达顺序、批次划分、
  并发度无关；同一输入流任意重排后，最终归属与画像逐项一致。
- **幂等**：信号按 ID 去重，重复到达（包括重启后重放）不重复应用、不改变结果。
- **增量维护**：普通接入只重算受影响的身份簇，不做全量重算；
  合并/撤销/拆分/删除等罕见管理操作走确定性全量重建。
- **手工合并**：`Merge(a, b)` 记录一条合并事件并生效；`UndoMerge(id)` 将其标记撤销，
  被撤销的合并在后续读取与重启重放中永不复活。撤销只移除该合并边，
  不影响其余身份簇，也不影响由信号本身形成的链接。
- **拆分**：`Split(id, ruleID)` 按配置规则（内置 `by-channel`：先按渠道分组、
  再按组内连通性细分）把簇拆开，判定依据（rationale）随拆分记录持久化。
  拆分通过"分组命名空间"实现：被拆分信号的标识在各自分组内独立成点；
  之后新信号或手工合并携带原始标识到达时，会把所有分组变体重新连通——
  即拆分后再走正常归并，成员与画像与直接归并一致。
- **历史时点查询**：`QueryAsOf(id, version)` 返回不晚于该版本的完整画像，
  合并前、合并期间、撤销后的状态都可见（已删除主体除外）。

## 冲突消解规则

同一属性的多个候选取值按如下**全序**选出唯一胜出值，因此结果可复现、可解释：

1. **来源优先级**：`Config.SourceRules` 配置的渠道优先级，越大越优先；
2. **取值可信度**：信号属性的 `Confidence`（0..1），越大越优先；
3. **时间新近度**：属性的 `ObservedAt`，越新越优先；
4. **值字典序**：完全并列时字典序小者胜（兜底，保证与到达顺序无关）。

每个属性的消解结果都记录在 `Profile.Resolutions` 中：胜出信号、全部候选信号、
人类可读的判定依据（`Reason`）。画像以簇为单位整体构建、整体发布，
任一时刻对外暴露的都是某个自洽的完整版本，不存在字段级混合。

## 同意与权限

- 信号携带 `Consent`；未同意 `Config.ProfilePurpose` 用途的信号**不得进入画像**
  （仍参与身份链接）。
- 读取按 `Reader.Scopes`（渠道集合，`*` 为全部）鉴权：读者须覆盖簇内任一成员
  信号的渠道；跨权限读取被拒绝并写入审计日志。
- `Erase(id)` 删除主体：移除其全部身份信号与派生画像（含历史版本链），
  并对全部关联标识放置墓碑——迟到的相同信号在接入时被拒绝
  （`ErrErasedSubject`），并发写入与重启重放都不会让已删除内容复活。

## 可靠性与并发

- **写入路径**：所有变更先追加 WAL 并 `fsync`，再应用到内存视图；
  批次以 `batch-begin`/`batch-commit` 包裹，崩溃留下的未提交批次在重放时被丢弃，
  不留部分写入。
- **读取路径**：已提交状态以不可变 `view` 原子发布，读者无锁，
  慢查询不阻塞信号接入，也不拖垮整体吞吐。
- **审计**：合并、撤销、拆分、删除、跨权限拒绝均留痕（`Engine.Audit()`）。

## 配置项（`Config`）

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| `DataDir` | 本地 WAL 存储目录 | 必填 |
| `SourceRules` | 渠道优先级列表（`Priority` 越大越优先） | crm=100, app=80, web=50, offline=10 |
| `SplitRules` | 拆分规则（内置 `by-channel`） | `[by-channel]` |
| `Budgets.MaxSignalsPerBatch` | 单批信号数上限，超限整批拒绝（`ErrBatchTooLarge`） | 1000 |
| `Budgets.MaxBatchDuration` | 单批处理时间上限，超时拒绝（`ErrBatchTimeout`） | 5s |
| `Budgets.MaxSignalsInMemory` | 内存信号总量上限，超限拒绝（`ErrMemoryLimit`） | 100000 |
| `ProfilePurpose` | 进入画像所需的同意用途 | `profile` |

超限与异常信号都在 `BatchResult.Items` 中给出可区分（状态 + 错误类别）、
可定位（信号 ID）的处理结果，不静默丢弃。

## 测试覆盖

`identity/` 下的自动化测试覆盖：乱序/重复/迟到/任意批次划分下的确定性、
属性冲突消解次序与可解释性、画像版本自洽性、误合撤销（含重启不复活）、
拆分再归并一致性、并发采集与查询（`-race`）、跨权限拒绝与审计留痕、
删除防复活（含并发竞争）、未提交批次丢弃、重启恢复。
